# Mamaearth Returns & Growth Intelligence Pipeline

## Project Overview

This project analyzes Mamaearth customer, product, and order data to identify revenue trends, return-risk patterns, data-quality issues, and actionable business insights.

The project consists of three main stages:

1. SQL analysis
2. Python/Pandas data cleaning, exploratory data analysis (EDA), and visualization
3. GenAI-powered business insight narration using Google's Gemini API, with an offline fallback

# Part 3 — GenAI-Powered Insight Narrator

## Project Objective

The GenAI narrator converts the verified findings from Part 2 into a Situation–Complication–Resolution (SCR) business narrative.

Instead of manually writing insights from analytical results, the narrator uses the findings generated by the Python pipeline to produce a structured business explanation.

The narrator reads the verified findings from:

`narrator/findings.json`

## Gemini Model Configuration

The project uses Google's Gemini API for AI-assisted business insight narration.

**Configured model:** `gemini-3.5-flash-lite`

This model successfully generated a response during a basic Google Colab test. The complete business-narrative generation must also be tested to confirm that the model works with the project's findings, prompt, and output-validation logic.

## Gemini API Key Configuration

The Gemini API key must be configured through the `GEMINI_API_KEY` environment variable.

### Windows PowerShell

Set the key for the current PowerShell session:

```powershell
$env:GEMINI_API_KEY="YOUR_GEMINI_API_KEY"
```

Replace the placeholder with your own API key. Never commit the actual key to GitHub.

### Google Colab

The API key can be loaded using Colab Secrets or a password-style input prompt.

For example, this code loads the key for the current runtime session without displaying it:

```python
import os
from getpass import getpass

os.environ["GEMINI_API_KEY"] = getpass(
    "Enter your Gemini API key: "
)

print("API key loaded for this session.")
```

This method keeps the key out of the source code. You may need to enter it again after restarting the Colab runtime.

**Security note:** Never hardcode your actual API key in the Python script, publish it in a notebook, or commit it to GitHub.

## Run the Narrator

From the project root, run:

```bash
python narrator/generate_narrative.py
```

The script attempts to generate the SCR narrative using the configured Gemini model.

The generated narrative is intended to explain the key findings, business risks, and potential actions based on the verified analytical results.

## Offline Fallback

The project also supports a deterministic offline fallback.

If the `GEMINI_API_KEY` environment variable is missing, or if the Gemini API call fails, the existing fallback is designed to generate a narrative without relying on the Gemini service.

The offline fallback does not require an API key or an internet connection.

The generated output is saved to:

`narrator/sample_output.txt`

The offline fallback helps preserve reproducibility when the external API is unavailable.

## Output Validation

The narrator includes a required-figures checker to help validate important business values in the generated output.

After running the script:

1. Review `narrator/sample_output.txt`.
2. Confirm that the narrative reflects the findings in `narrator/findings.json`.
3. Verify the required financial and return-risk figures.
4. Confirm that the offline fallback continues to work if Gemini is unavailable.

The model change should not modify the SQL pipeline, Python data-cleaning logic, verified findings, or existing offline fallback.

# Business Insights

## 1. Cash-on-Delivery Return Risk

COD has the highest return rate among the three payment methods analyzed, at 44.4%.

This indicates that COD orders warrant closer monitoring and further investigation into the factors associated with returns.

## 2. High-Risk Customer Segment

The highest-risk segment is COD in Tier-2 cities, with a return rate of 54.5%.

Regional operations could prioritize this segment for further analysis and targeted return-reduction initiatives.

## 3. Duplicate Reconciliation

Duplicate records created a reconciliation delta of ₹2,501.90 between the raw and cleaned revenue figures.

This demonstrates why duplicate detection and reconciliation are important for reliable financial reporting.

## 4. Revenue Trend and Outlier Impact

January initially appeared to be the highest-revenue month, with revenue of ₹29,582.10.

After accounting for the quantity outliers, January's corrected revenue was ₹11,637.10. March 2026 became the true peak month, with revenue of ₹20,318.90.

This demonstrates how extreme values can distort monthly revenue comparisons and why outlier analysis is important.

## Business Recommendations

Based on these findings:

- Investigate COD return drivers, particularly in Tier-2 cities.
- Review order-confirmation and delivery processes for high-risk segments.
- Maintain duplicate detection and reconciliation controls.
- Use cleaned and reconciled data for revenue reporting.
- Monitor monthly revenue trends alongside outlier flags to avoid misleading conclusions.

These recommendations are based on the analyzed dataset and should be validated against additional operational data before implementation.
